ТЗ на тестовый frontend сервиса пробных экзаменов
1. Задача

Разработать простой web-интерфейс для тестирования backend сервиса пробных экзаменов.

Frontend должен работать как с серверной версией приложения, так и локально через Probnik.exe.

Дизайн: светлый минималистичный интерфейс в стиле ранее сделанных макетов:

белый/светло-серый фон;
фиолетовый основной акцент;
карточки с небольшим скруглением;
простые таблицы;
цветные статусы;
без сложной анимации;
desktop-first, но с нормальным отображением на телефоне.

Главная цель первой версии — проверить бизнес-логику, а не добиться идеального дизайна.

2. Роли

Поддержать три интерфейса:

Ученик
Учитель
Администратор / Ответственный

Администратор и Ответственный на первом этапе можно реализовать практически одним интерфейсом.

Это важно для минимизации повторяющегося кода.

14. Работа с API

Frontend не должен содержать бизнес-логику базы.

Схема:

Frontend
   ↓
API client
   ↓
FastAPI
   ↓
Services
   ↓
Database

Все запросы к backend вынести в одно место, например:

src/api/

Не писать fetch() непосредственно внутри каждой страницы.

Например:

api.students.list()
api.exams.list()
api.exams.create()
api.participations.updateStatus()
api.results.save()
api.results.publish()
api.import.preview()
api.import.apply()

Не делать чрезмерное количество слоёв и файлов.

16. Что пока НЕ нужно

Для первой тестовой версии не реализовывать:

сложные графики;
уведомления;
Telegram/email;
красивую аналитику;
экспорт PDF;
мобильное приложение;
сложные настройки прав;
восстановление паролей;
дизайнерские анимации;
отдельную страницу для каждого вида экзамена.

Главная задача — пройти полный сценарий:

Excel CRM
   ↓
импорт
   ↓
создание пробника
   ↓
запись ученика
   ↓
контроль явки
   ↓
сдача работы
   ↓
проверка учителем
   ↓
публикация
   ↓
просмотр результата учеником
Критерий готовности frontend

Frontend считается достаточным для первого тестирования, если на нём можно полностью пройти этот сценарий без обращения к Swagger или прямого редактирования базы.

Это как раз даст вам первую рабочую версию, на которой уже станет понятно, что в модели данных и процессе нужно изменить до разработки полноценного интерфейса.
