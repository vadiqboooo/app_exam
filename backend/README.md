# Пробник — backend

Рабочая основа по `../backend.md`: Python 3.12+, FastAPI, SQLAlchemy, SQLite и Alembic.
Один процесс приложения, шесть предметных сущностей, отдельные файлы по ответственности.
Версии зависимостей зафиксированы в `uv.lock`.

## Запуск в Windows / PowerShell

Из папки `backend/`, с установленными Python и `uv`:

```powershell
uv sync --locked
uv run python -m app init-db
$env:API_KEY = uv run python -c "import secrets; print(secrets.token_urlsafe(32))"
uv run uvicorn app.main:create_app --factory --reload
```

Открыть http://127.0.0.1:8000/docs. Ключ из `$env:API_KEY` вставить в **Authorize**.
Операторские `/api/*` требуют `Authorization: Bearer <ключ>`; `/health` открыт.
Ученический `/api/student/*` использует отдельный подписанный токен; тестовый вход — по имени.
Без `API_KEY` доступ к данным закрыт. Ключ задаётся через окружение; `.env` автоматически не читается.
Команда выше генерирует новый ключ на каждый запуск: для постоянной установки сохраните его
в окружении службы. Отдельные учётные записи сотрудников пока не реализованы.

По умолчанию создаётся `backend/data/probnik.db`, независимо от рабочей папки.
Другой путь задаётся через `DATABASE_URL`, например `sqlite:///C:/probnik/data/probnik.db`.
Создание и изменение схемы выполняется только миграциями, не при каждом запуске HTTP-сервера.

На VPS используются те же команды и база. Задайте постоянные `API_KEY` и `DATABASE_URL`
в окружении службы; запускайте Uvicorn без `--reload` за HTTPS reverse proxy.
SQLite рассчитана на один сервер с локальным диском и последовательной записью.
Не размещайте рабочую базу в папке облачной синхронизации или на общем сетевом диске.
В этом рабочем каталоге используется OneDrive: для постоянной работы задайте путь вне OneDrive.

## Структура

```text
app/
  main.py                  сборка приложения и подключение маршрутов
  config.py                настройки окружения
  database.py              соединения, транзакции, SQLite PRAGMA
  models/                  одна сущность БД — один файл
  schemas/                 проверка входных данных и форматы ответов
  api/                     маршруты по предметным областям
  importers/
    record.py              независимый формат записи CRM
    excel.py               чтение и настройка формата Excel
  services/
    sync.py                синхронизация и предварительный отчёт
    participation.py       переходы статусов и проверка результатов
    backup.py              резервное копирование SQLite
migrations/                версионирование схемы
tests/                     сценарии API, импорта, истории и backup
```

Направление зависимостей: HTTP → сервис → модели; Excel → `StudentRecord` → синхронизация.
Сервисы не зависят от FastAPI и подходят для будущего локального интерфейса или CLI.
SQLAlchemy Session уже управляет доступом к данным: дополнительного слоя универсальных
репозиториев, базовых CRUD-классов и DI-контейнера нет.

Новую возможность добавляйте отдельным сервисом и роутером; роутер подключается в `main.py`.
При изменении схемы добавьте модель в `models/__init__.py`, затем:

```powershell
uv run alembic revision --autogenerate -m add_feature
# Просмотреть сгенерированную миграцию перед применением.
uv run python -m app init-db
```

## Импорт CRM

Формат проверен на реальной выгрузке `Список.xlsx` и на тестовых XLSX:
первый лист, первая строка — заголовки, одна строка на ученика.

| Колонка | Содержимое |
| --- | --- |
| ФИО | Обязательно |
| Статус обучения | `Обучается`, `Активен`, `Архив`, `Не обучается`, `Неактивен` |
| Активные группы | Названия через запятую, `;` или перенос строки; допускается пустая ячейка |
| Класс обучения | Целое число 1–11 или пустая ячейка |
| ID | Необязательная колонка с постоянным ID CRM; текст сохраняет ведущие нули |

Регистр заголовков и статусов не важен. Неизвестные статусы, дубли и формулы отклоняются.
Другие названия колонок, статусы и разделитель настраиваются в `ExcelFormat` импортёра.
У одного ученика сохраняются все перечисленные группы. Сначала запятые и `и` между
днями недели заменяются на `-`: `ПН, СБ` и `ПН и СБ` → `ПН-СБ`.
Время тоже учитывается: `Вт 18:00, ПТ 16:30` → `Вт 18:00-ПТ 16:30`.
Оставшиеся запятые, точки с запятой и переносы строк разделяют группы.
Лишние пробелы и повторы нормализованных названий убираются.
Название хранится целиком с этими заменами. API групп дополнительно
выделяет для отображения предмет, преподавателя и расписание из узнаваемых названий
CRM; при недостатке данных возвращает `null`. Явно заданные в базе предмет и
преподаватель имеют приоритет над разбором названия.
Явный `ExcelFormat.group_separator` задаёт собственное регулярное выражение вместо
автоматического разбора, например для названий с запятыми вне расписания.

1. `POST /api/imports/analyze`: загрузить файл в поле `file`; получить `total` и
   `grades: [{grade: 11, count: 25}, {grade: null, count: 2}]`. Записи в БД не меняются.
2. `POST /api/imports/preview`: передать файл и поле формы `grades` — JSON-массив
   выбранных классов, например `[9, 11, null]`. `null` обозначает «Без класса».
   Пустой выбор или выбор без учеников в файле отклоняется.
3. Посмотреть `report`: `total` (ученики выбранных классов), `unchanged`, `new`, `returned`, `left`, `updated`,
   `changed_groups`, `new_groups`, `memberships_added`, `memberships_closed`.
4. После подтверждения оператором отправить тот же файл и тот же `grades` в `POST /api/imports/apply`
   и передать строку `confirmation` из предварительного ответа в одноимённом поле формы.

**Каждый файл — полная выгрузка CRM.** При выборе классов добавляются и обновляются
только ученики этих классов. Отсутствующие ученики архивируются только в выбранных классах.
Ученик, переведённый в файле в невыбранный класс, остаётся без изменений даже при прежнем
выбранном классе в базе. Сопоставление выполняется по полному файлу до фильтрации.
Без поля `grades` API сохраняет прежний режим синхронизации всех классов.
Выгрузка одной группы не подходит. Неактивный статус также закрывает текущие связи.
Пустой файл по умолчанию отклоняется: намеренная архивация всех требует `allow_empty=true`
и на просмотре, и на применении. `changed_groups` — дополнительный счётчик, он пересекается
с категориями учеников; `left` включает отсутствующих в файле.

Просмотр выполняет тот же алгоритм в откатываемой транзакции. Подтверждение учитывает файл,
выбор классов, состояние учеников/групп/связей и текущую дату UTC. После изменения нужен новый просмотр.
Применение целиком атомарно. В SQLite операции записи сериализуются через `BEGIN IMMEDIATE`.

Постоянный ID имеет приоритет над ФИО. Если ID появился впервые, он присоединяется к
единственной записи с таким ФИО без ID. Неоднозначные совпадения отклоняются.
Без ID изменение ФИО нельзя надёжно отличить от нового ученика: старая запись архивируется,
новая создаётся. История сохраняется, но автоматического объединения таких записей нет.
Возврат в группу создаёт новую Membership; существующие результаты не изменяются.

## Экзамены и результаты

Через `/docs` доступны:

| Метод и путь | Назначение |
| --- | --- |
| GET `/api/students` | Поиск по ФИО, фильтр активности, пагинация |
| GET `/api/students/{id}/memberships` | История групп |
| GET `/api/groups` | Текущие и архивные группы |
| POST / GET `/api/exams` | Создание и список пробников / ЕГЭ |
| GET / POST / PUT / DELETE `/api/subjects` | Шаблоны заданий по предметам и типам ОГЭ/ЕГЭ |
| POST / GET `/api/participations` | Запись и результаты; фильтры `student_id`, `exam_id` |
| PATCH `/api/participations/{id}/status` | Смена статуса |
| PUT `/api/participations/{id}/result` | Полная замена результата проверки |

Основная цепочка: `registered → attended → submitted → checked → published`.
Из `registered` возможны `absent` и `cancelled`; из них можно вернуться в `registered`.
Результат записывается в `submitted` или `checked`; для `checked` нужен первичный балл.
После публикации результат закрыт для изменений. Повторная запись на тот же экзамен даёт 409.

Время передаётся с часовым поясом (`2026-10-01T15:00:00+08:00`), хранится в UTC,
возвращается с `Z`. Даты Membership также используют UTC.
Баллы по заданиям проверяются по структуре экзамена: все коды должны присутствовать,
баллы не превышают максимум, сумма совпадает с первичным баллом.
Настройка предмета хранит отдельный список заданий для ОГЭ или ЕГЭ. При создании события
активный шаблон копируется в `Exam.structure_data`, поэтому изменение или удаление настройки
не меняет структуру уже созданного пробника.
Можно сохранить только итоговые баллы, например при переносе результата ЕГЭ.
Этот API предназначен для оператора и позволяет вводить исторические результаты;
окно регистрации пока хранится в модели, но не ограничивает действия оператора.

## Резервная копия

```powershell
uv run python -m app backup backups/probnik_2026-09-18.db
```

Используется SQLite Backup API, включая данные из WAL. Существующий backup не перезаписывается.
Для работы с копией укажите её путь в `DATABASE_URL`, примените миграции и запустите приложение.
Перед заменой рабочей базы остановите использующее её приложение.
При работающем сервере переносите именно результат команды backup.

## Проверки и дальнейшее развитие

```powershell
uv run pytest -q
uv run ruff check app tests migrations
uv run alembic check
```

Тесты создают временные базы через настоящую миграцию. Проверяются полный цикл экзамена,
повторные импорты, сохранение истории, неоднозначные ФИО, откат транзакции,
устаревшее подтверждение, внешние ключи и переносимость backup.

Клиентские интерфейсы находятся в `../frontend/`; инструкции запуска — в `../README.md`.
Следующие этапы: отдельные учётные записи сотрудников,
код доступа ученика и проверка прав по ролям. Таблица Staff пока подготовлена на уровне модели.

Модели и миграция используют типы SQLAlchemy, совместимые с PostgreSQL, и частичный уникальный
индекс для активных связей обеих СУБД. Переход потребует установки драйвера psycopg,
смены `DATABASE_URL`, переноса данных и интеграционной проверки на PostgreSQL;
работа с реальным PostgreSQL в этой версии не проверялась. Несколько серверов с общей SQLite
не предусмотрены. Для PostgreSQL резервное копирование выполняется средствами самой СУБД.

Основа организации модулей: [FastAPI APIRouter](https://fastapi.tiangolo.com/tutorial/bigger-applications/).
Настройка транзакций и связей: [SQLAlchemy SQLite](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html).
