# Пробник

Тестовый сервис пробных экзаменов: импорт CRM, запись учеников, явка, проверка и публикация результатов.
Код разделён на `backend/` и `frontend/`.

```text
backend/                  Python / FastAPI / SQLAlchemy / SQLite
  app/                    API, модели, сервисы, импортёр
  migrations/             миграции Alembic
  tests/                  проверки backend
  data/probnik.db          рабочая база (не включается в Git)
  desktop.py              локальный запуск
  pyproject.toml, uv.lock  зависимости Python
frontend/                 React / TypeScript / Vite
  src/api/                все HTTP-запросы
  src/components/         общие таблицы, формы и карточки
  src/pages/              интерфейсы сотрудника, учителя и ученика
  src/layouts/            навигация и загрузка данных кабинетов
  src/styles/             светлая тема с фиолетовым акцентом
  tests/                  сквозной сценарий в браузере
scripts/                  запуск и сборка Probnik.exe
backend.md, frontend.md   исходные технические задания
```

Существующая база перенесена из `data/` в `backend/data/`. Тесты используют отдельные временные базы.

## Запуск на чистом компьютере (без Python и Node.js)

**Windows:** дважды щёлкните `start.cmd` в корне проекта (нужен только интернет). **macOS / Linux:**
`curl -LsSf https://astral.sh/uv/install.sh | sh`, затем `uv run scripts/run_local.py`.

Скрипт сам ставит `uv` (без прав администратора); `uv` скачивает Python, а интерфейс собирается с
Node.js из пакета `nodejs-wheel-binaries`. Он применяет миграции, запускает приложение на
`127.0.0.1:8000` (если порт занят, берёт следующий), открывает браузер и печатает **код доступа**:
«Сотрудник» → «Администратор» → вставьте код. Код создаётся один раз и запоминается.

**Бэкапы сразу.** При первом запуске спросит ID приложения Яндекса (подсказывает, где его взять:
oauth.yandex.ru, с двумя Callback URL, см. раздел про развёртывание) и сам получит токен: откроет
браузер, вы нажмёте «Разрешить», токен вернётся скрипту. Тогда на вкладке «Школа → Резервные копии» вход Яндекса открывается без ввода ID, а
с токеном копии доступны сразу; на новой базе скрипт предложит восстановить последнюю копию
(`--restore-latest` делает это без вопроса). Без ID и токена всё подключается позже в приложении.

Данные (база, токен Яндекса, код доступа, журнал `server.log`) лежат в профиле пользователя:
`%LOCALAPPDATA%\Probnik` (Windows), `~/Library/Application Support/Probnik` (macOS),
`~/.local/share/probnik` (Linux), а не в проекте и не в OneDrive. Другая папка: `--data-dir`.
Остальное: `--yes` (без вопросов), `--no-browser`, `--yandex-client-id`, `--yandex-token`,
`--smoke` (запустить, проверить и остановить). Чтобы перенести данные на другой компьютер, сделайте
копию в «Резервные копии» и восстановите её там же.

## Быстрый локальный запуск (для разработки)

Нужны Python 3.12+, `uv`, Node.js 22.12+ (или 24+) и npm. Из корня проекта в PowerShell:

```powershell
./scripts/start-local.ps1
```

Скрипт устанавливает зависимости, собирает клиент, применяет миграции и открывает браузер.
Вход в локальный кабинет администратора происходит автоматически. Сервер слушает только
`127.0.0.1`; база — `backend/data/probnik.db`.

Ключ для повторного входа сотрудников отображается в окне локального сервера.
Нажмите **Выйти**, чтобы открыть интерфейс учителя или ученика. Для остановки закройте
окно сервера или нажмите Ctrl+C. Ключ создаётся заново при запуске, если `API_KEY` не задан.

## Разработка

Первый терминал:

```powershell
cd backend
uv sync --locked
uv run python -m app init-db
$env:API_KEY = 'garry'
uv run uvicorn app.main:create_app --factory --reload
```

Второй терминал:

```powershell
cd frontend
npm ci
npm run dev
```

Клиент: http://127.0.0.1:5173. Vite перенаправляет `/api` на порт 8000.
Ключ находится в сеансе браузера, а не в сборке JavaScript.
Документация API: http://127.0.0.1:8000/docs; обычные операции доступны через интерфейс без Swagger.

## Сценарий проверки

1. Войти как **Сотрудник → Администратор** с ключом сервера.
2. В **Импорте CRM** загрузить полную XLSX-выгрузку. Посмотреть количество учеников
   по классам, отметить нужные классы (или «Без класса») и нажать **Показать изменения**.
   Проверить списки, нажать **Применить изменения** и подтвердить.
3. В **Предметах** настроить отдельные шаблоны ОГЭ и ЕГЭ: задания и максимальный
   первичный балл за каждое. Затем в **Пробниках** создать экзамен и указать расписание.
4. Выйти. Войти учеником по фамилии и имени из списка и записаться на пробник.
5. Войти сотрудником по ключу или учителем по фамилии и имени. Отметить **Пришёл → Сдал работу**.
6. Внести баллы и комментарии. **Сохранить** переводит работу в «Проверено»,
   но ещё не показывает результат ученику.
7. **Опубликовать результат** сохраняет и публикует результат одной транзакцией.
8. В кабинете ученика открыть **Мои результаты** и подробный разбор.

Для быстрого внесения уже проверенной работы откройте **Экзамены и результаты → Добавить результат**:
выберите экзамен и ученика, заполните компактную сетку заданий и итоговый балл. Если ученик ещё не был
зарегистрирован, операторская запись создаётся автоматически со статусом «Проверено». Обычный сценарий
регистрации, явки, сдачи и публикации при этом остаётся доступен.

Учитель видит группы и учеников, в том числе ещё не записавшихся на выбранный пробник.
В «Моих группах» показана таблица: название, предмет, преподаватель, расписание и число
учеников. Нажмите строку, чтобы открыть группу; «Назад к группам» возвращает на прежнюю
страницу таблицы. Предмет, преподаватель и расписание выделяются из названия CRM
во время импорта; недостающие сведения отмечены как «Не указан».
Внутри группы учитель выбирает пробник по предмету группы и раскрывает строку ученика.
Для каждого задания показывается заданный администратором максимальный балл; первичный
балл считается автоматически. Здесь же можно указать итоговый балл и общий комментарий
по работе. **Сохранить** оставляет результат внутренним, **Опубликовать** показывает его
ученику. Результат можно внести и без предварительной записи ученика на время пробника.
Сотрудники используют общий операторский ключ и видят все группы центра. Учителя входят
по имени и отчеству из CRM и видят только назначенные им группы, учеников и результаты.
При импорте преподаватели из названий групп сохраняются в единой таблице `staff` с ролью
`teacher`, а группы связываются с ними через `teacher_id`. Администратор может добавлять,
переименовывать и удалять учителей, а также назначать им группы в разделе **Учителя**.
Ручное назначение имеет приоритет над следующим импортом CRM.

В разделе **Предметы** администратор создаёт отдельную настройку для каждой связки
«предмет + ОГЭ/ЕГЭ». В ней задаются номера заданий и максимальный первичный балл за
каждое задание; общий максимум рассчитывается автоматически. При создании пробника
текущая структура предмета копируется в него. Последующие изменения настроек не меняют
старые пробники и результаты. Скрытый предмет не предлагается в новых пробниках.
При установке создаются 20 настроек ОГЭ/ЕГЭ, перенесённых из `crm_school_g/school_new.db`:
биология, химия, английский язык, география, история, информатика, математика,
физика, русский язык и обществознание в доступных в исходной базе форматах.

У ученика отдельный подписанный сеанс на 8 часов: API возвращает только его участия и
опубликованные результаты. Проверка доступа выполняется на сервере. Вход по имени —
тестовый режим из ТЗ, он не подтверждает личность. Его можно отключить через
`STUDENT_TEST_LOGIN=false`. Код доступа позже добавляется в отдельную схему и обработчик
входа без изменения страниц кабинета.

## Формат Excel

Первый лист, заголовки в первой строке. Одна строка на ученика.

| Колонка | Значение |
| --- | --- |
| ФИО | Фамилия Имя Отчество, отчество необязательно |
| Статус обучения | Обучается / Активен / Архив / Не обучается / Неактивен |
| Активные группы | Названия через запятую, `;` или перенос строки; у ученика может быть несколько групп |
| Класс обучения | Число 1–11 или пусто |
| ID | Необязательный постоянный ID CRM |

Настройки формата находятся в `backend/app/importers/excel.py`.
Парсер проверен на реальной выгрузке `Список.xlsx`. Сначала `и` и запятые между
днями недели заменяются на `-`: `ПН и СР` → `ПН-СР`, `ПН, СБ` → `ПН-СБ`,
`Вт 18:00, ПТ 16:30` → `Вт 18:00-ПТ 16:30`. Затем оставшиеся запятые разделяют
группы ученика. Точка с запятой и перенос строки также разделяют группы.
Лишние пробелы и повторы групп после замены убираются.
После обновления повторно импортируйте полную выгрузку: прежние варианты названий
уйдут в архив, а ученики получат связи с группами с нормализованными названиями.
Файл всегда рассматривается как **полная выгрузка**, но импорт в интерфейсе затрагивает
только выбранные классы. Ученики остальных классов не добавляются и не архивируются.
Отсутствующие в файле ученики выбранных классов архивируются. Ученики, которые в файле
перешли в невыбранный класс, остаются без изменений до импорта этого класса.
История групп и результаты сохраняются. Если после просмотра изменилась база, файл, выбор классов или дата,
применение отклоняется — нужно повторить анализ.

### Мастер импорта (Школа → Импорт CRM)

Три шага: прошлая версия → группы и ученики → итог. На втором шаге можно выбрать сразу
несколько актуальных XLSX-файлов из разных школ. Файлы объединяются в одну полную
выгрузку: повторяющийся ученик получает связи со всеми своими группами. Учителя берутся
из колонки ответственного педагога, а предмет и тип экзамена — из названия группы.

Импорт применяется одной транзакцией кнопкой «Применить импорт» после общего
предпросмотра. Если после просмотра изменились файлы, дата или база, применение
отклоняется. Учителя, ученики и группы, которых нет ни в одном из выбранных файлов, архивируются;
история групп, составов и результаты сохраняются.

На странице «Школа → Группы» администратор может изменить название, предмет, тип
экзамена и назначенного учителя, а также вручную перевести группу в архив. Ручной архив
не отменяется следующим импортом; такая группа и её текущий состав скрыты от учителя.

Тема оформления выбирается в настройках конкретного пробника при его создании или
редактировании. Если хотя бы у одного активного пробника выбрана тема «Хэллоуин», на
странице входа появляется кнопка «Воспользоваться магией». Когда тема отключена во всех
активных пробниках, кнопка исчезает, а ранее выбранное оформление сбрасывается на обычное.

| Файл | Колонки (первый лист, заголовки в первой строке) |
| --- | --- |
| Группы и ученики `.xlsx` | `Название`, `Клиенты`, `Отв. педагог` (обязательно), `Статус` (необязательно) |
| Прошлая версия `.db` | SQLite старого приложения `exams_g`: таблицы `student` (`fio`) и `exam` (`subject`, `answer`, `comment`), необязательно `probnik` |

В `Клиенты` ученики перечисляются через запятую, точку с запятой или перенос строки.
Поддерживаются названия предметов в любом регистре и сокращения `РУССКИЙ ЯЗ`;
`ОГЭ`/`ЕГЭ` можно ставить до или после предмета. Класс берётся из явной записи вроде
`10 КЛАСС`, иначе для ОГЭ используется 9 класс, для ЕГЭ — 11. При противоречивых данных
класс ученика остаётся не указан. Старые раздельные API импорта учителей, групп и учеников
оставлены для обратной совместимости.

Работы прошлой версии сопоставляются с учениками по точному ФИО (повторяющиеся ФИО не
привязываются), а предметы — по кодам старой базы (`math_profile`, `rus`, `infa`,
`math_9` и т. д., список в `backend/app/services/school_import.py`). Они попадают в
отдельный пробник с названием из старой базы со статусом «Проверено» и автором
«Прошлая версия» и **не публикуются**. Баллы по заданиям переносятся, только если число
заданий в строке совпадает со структурой предмета в «Предметах». Повторная загрузка не
создаёт дубли.

## Развёртывание на VPS одной командой

Скрипт `scripts/deploy.py` ставит приложение на чистый VPS (Ubuntu или Debian, вход root по паролю).
**На вашем компьютере ничего ставить заранее не нужно** (ни Python, ни Node.js; git нужен только для обновления из git): достаточно
интернета. На Windows дважды щёлкните `deploy.cmd` в корне проекта (или запустите его из
терминала). Он сам поставит `uv` без прав администратора, `uv` скачает Python и библиотеки, а
интерфейс соберётся с Node.js из пакета `nodejs-wheel-binaries`.

На macOS / Linux: `curl -LsSf https://astral.sh/uv/install.sh | sh`, затем `uv run scripts/deploy.py`.
Если `uv` уже есть, везде работает та же команда:

```powershell
uv run scripts/deploy.py
```

Скрипт спросит и покажет шаги:

1. **IP VPS и пароль root.** Скрипт предложит запомнить доступ: адрес, пользователь и порт лежат в
   `scripts/.deploy.json` (в git не попадает), а **пароль хранится в системном хранилище** (на Windows
   «Диспетчер учётных данных»), не в файле. В следующий раз вводить ничего не надо. Забыть пароль:
   `uv run scripts/deploy.py --forget`.
2. **ID приложения Яндекса** и, по желанию, **токен**: ID попадает в настройки, и на вкладке
   «Резервные копии» сразу открывается вход Яндекса; с токеном бэкапы работают сразу, а на новой базе
   скрипт предложит восстановить последнюю копию из облака. Как их получить, скрипт подсказывает сам:
   на https://oauth.yandex.ru/client/new создайте приложение (платформа «Веб-сервисы», права
   «Яндекс.Диск REST API → Доступ к папке приложения») и в **Callback URL добавьте два адреса**:
   `https://oauth.yandex.ru/verification_code` и `http://localhost:8765/`. Скопируйте «ID приложения».
   **Токен копировать не нужно:** скрипт откроет браузер на странице Яндекса, вы нажмёте «Разрешить», и
   токен вернётся скрипту сам (на минуту поднимается страница на `localhost:8765`, она слушает только
   этот компьютер и принимает один токен). Если Callback URL `localhost` не добавлен или порт занят,
   скрипт предложит вставить токен вручную.
3. **Домен** (можно пропустить и работать по IP) и e-mail для сертификата. Если домен в **Timeweb
   Cloud**, скрипт сам создаст для него A-запись на IP сервера: нужен только токен из
   https://timeweb.cloud/my/api-keys («Создать токен»), домен должен быть добавлен в раздел «Домены»
   и использовать DNS Timeweb. Дальше скрипт ждёт (до 10 минут), пока сервер увидит домен на своём
   адресе, и выпускает сертификат Let's Encrypt: сайт открывается по `https://ваш.домен`, а `http://`
   перенаправляется на него. Токен можно передать параметром `--timeweb-token` или переменной
   `TIMEWEB_TOKEN`. Если у домена уже есть запись на другой адрес (или CNAME), она **не заменяется без
   вашего согласия**: скрипт спросит, а без вопросов нужен параметр `--replace-dns`. Нет токена или
   домена нет в этом аккаунте: добавьте запись сами (тип A, имя домена, IP сервера), скрипт дождётся её.

Шаги: собираю приложение → подключаюсь → **смотрю, что уже работает на сервере** → доустанавливаю
недостающее (пакеты, пользователь `probnik`, `uv`) → загружаю приложение → создаю код доступа →
ставлю зависимости и базу → запускаю службу `probnik` (systemd) → подключаю сайт к nginx → открываю
порт в файрволе (если он включён) → подключаю домен и HTTPS (если указан) → проверяю.

**Если на сервере уже работает другой проект**, скрипт ему не мешает:

- смотрит занятые порты (`ss`) и выбирает свободные: внутренний порт приложения (с 8000) и порт сайта;
- **файрвол сам не включает.** Если `ufw` выключен, он остаётся выключенным; если включён, добавляется
  только правило для нужного порта (и 443 для домена), существующие правила не меняются;
- nginx: чужие сайты и конфиги не трогаются, стандартный сайт nginx удаляется только у свежеустановленного
  nginx. Если порт 80 свободен и nginx не было, сайт открывается на 80 по IP; иначе на свободном порту
  (с 8080), а домен делит порт 80 с остальными сайтами по имени. Если порт 80 занят не nginx (Apache,
  Docker), nginx ставится без запуска и сайт идёт на своём порту, домен и HTTPS пропускаются;
- новый сайт nginx проверяется командой `nginx -t`; если конфигурация не принята, он сразу убирается,
  и остальные сайты остаются как были;
- что сделано, записывается в `/opt/probnik/deploy-state.json`, чтобы выключение и удаление отменяли
  ровно это.

**Выключение.** Тем же скриптом (или пункт меню при запуске без параметров):

- `uv run scripts/deploy.py --stop`: приложение выключается, его сайт убирается из nginx, закрываются
  порты, которые открыл скрипт; данные и настройки остаются;
- `uv run scripts/deploy.py --start`: включить обратно;
- `uv run scripts/deploy.py --uninstall`: удалить приложение с сервера. Данные при этом переносятся в
  `/var/backups/probnik-data-<дата>` (стереть и их: `--delete-data`); требуется ввести слово `УДАЛИТЬ`
  (или `--yes`). nginx, `uv`, пакеты и чужие программы не затрагиваются.
В конце печатается адрес и **код доступа**: откройте адрес → «Сотрудник» → «Администратор» → вставьте
код. Потеряли код: пункт меню «Показать код доступа» (`--show-code`).

**Управление приложением на сервере.** `deploy.cmd` или `uv run scripts/deploy.py` без параметров
показывает меню (подключается по сохранённому доступу), те же действия есть параметрами:

- **Обновить** (`--update`): на git выложили изменения, одна команда доставляет их на сервер. Скрипт
  получает их через `git pull --ff-only` (если на компьютере нет несохранённых правок; незакоммиченное
  он не затирает, а выкладывает как есть и пишет об этом), собирает интерфейс, **делает копию базы на
  сервере** (`/var/backups/probnik-updates`, последние десять; в имени копии записана версия, с
  которой она сделана), выкладывает новую версию, обновляет схему
  базы и перезапускает службу. Данные и код доступа не меняются. Все пользователи работают с новой
  версией: страница приложения отдаётся без кэша, поэтому у всех она обновится при следующей загрузке.
  Версия (хеш коммита) и время обновления видны в состоянии. Если приложение выключено, сначала
  включите его. Если на сервере версия **новее**, чем в этой папке (например, открыта старая копия
  проекта), скрипт откажется выкладывать старое поверх нового; выложить всё равно: `--force`;
- **Вернуть прошлую версию** (`--rollback`, версия через `--to тег-или-хеш`, без параметра скрипт
  покажет список последних версий из git для выбора). На сервере ничего для этого не хранится:
  версия берётся из git, собирается на вашем компьютере и выкладывается как обычное обновление,
  ваша рабочая папка и незакоммиченные правки не затрагиваются. Скрипт сверяет миграции базы между
  версиями: если схема не менялась, возвращается только код и **данные остаются**. Если менялась,
  старый код не запустится на новой базе, и нужна копия базы той версии (она есть, если вы
  обновлялись этим скриптом, не более десяти последних). Скрипт скажет, что всё внесённое с тех пор
  **пропадёт**, и попросит ввести слово `ОТКАТ` (без вопросов: `--restore-db`); перед откатом
  делается копия текущей базы, так что к новой версии можно вернуться. Нет копии нужной версии: откат
  отменяется, ничего не меняя;
- **Показать код доступа** (`--show-code`) и **задать новый** (`--set-code`, свой код через `--code`
  или случайный). После смены старый код не работает, а вошедшие сотрудники и ученики входят заново
  (свои личные 6-значные коды они сохраняют). Сами личные коды хранятся в базе только в виде хеша:
  их можно сбросить в приложении («Школа» → «Ученики», «Сотрудники»), но не посмотреть;
- **Состояние и журнал** (`--status`): работает ли служба, отвечает ли сайт, версия, размер базы,
  последние строки журнала;
- выключить, включить, удалить (`--stop`, `--start`, `--uninstall`) и полное развёртывание с доменом и
  Яндексом (пункт 7 меню).

Для `--update` на компьютере нужен `git` и клон репозитория со связью с git-сервером; без них
скрипт выложит файлы, которые лежат на диске.

Скрипт можно запускать повторно: он обновляет приложение, не трогая данные (`/opt/probnik/backend/data`)
и код доступа. **Домен потом** добавляется тем же скриптом:
`uv run scripts/deploy.py --domain school.example.com --email me@example.com` (A-запись домена должна
уже указывать на IP, иначе приложение останется по HTTP). Без вопросов: `--yes` (пароль в переменной
`DEPLOY_PASSWORD`), `--restore-latest` восстанавливает на новой базе последнюю копию из облака,
`--dry-run` только показывает шаги и команды. Локальные данные, ключи и `client_secret.json` на сервер
не отправляются.

## Сервер / VPS (вручную)

Соберите frontend (`npm ci` и `npm run build` из `frontend/`), затем запустите backend
с постоянными `API_KEY` и `DATABASE_URL`. FastAPI раздаёт `frontend/dist` по `/`, API — по `/api`.
На VPS используйте Uvicorn без `--reload` за HTTPS reverse proxy. Клиент обращается к тому же
домену; отдельная настройка CORS не нужна. Hash-маршруты работают и локально, и на сервере.

SQLite храните на локальном диске вне OneDrive / сетевой синхронизации. Другой путь:

```powershell
$env:DATABASE_URL = 'sqlite:///C:/Probnik/data/probnik.db'
```

## Резервные копии в облаке

Вкладка «Школа → Резервные копии» (только администратор) выгружает копию базы в облако: снимок
SQLite сжимается в `probnik-ГГГГММДД-ЧЧММСС.db.gz` и загружается в папку. При проверке импорта на
шаге «Итог» показывается возраст последней копии; если копии нет, она старше 24 часов или облако
не настроено, появляется предупреждение со ссылкой на вкладку (импорт при этом не блокируется).

### Яндекс Диск через REST API (бесплатно)

1. На https://oauth.yandex.ru/client/new создайте приложение: платформа «Веб-сервисы», Callback URL
   `https://oauth.yandex.ru/verification_code`, право «Яндекс.Диск REST API → Доступ к папке
   приложения» (токен тогда видит только свою папку «Приложения/…»).
2. На вкладке вставьте ID приложения, нажмите «Открыть вход Яндекса», разрешите доступ и скопируйте
   показанный токен.
3. Вставьте токен и нажмите «Подключить Яндекс Диск».

Приложение проверит токен и сохранит его в `data/yandex.json` рядом с базой (не в самой базе, чтобы
токен не попадал в копии). Токен Яндекса живёт до года; когда истечёт, подключите заново.
«Отключить» удаляет файл. Если выдать право на весь диск, копии лягут в папку «Probnik backups».

### Папка, синхронизируемая с облаком (без API, работает с любым облаком)

1. Установите на этот компьютер бесплатное приложение облака: «Яндекс Диск», Google Drive для
   компьютеров, Dropbox или OneDrive.
2. В его папке создайте подпапку, например `Yandex.Disk\Probnik backups`.
3. На вкладке вставьте путь к этой подпапке и нажмите «Подключить папку».

Приложение кладёт копии в эту папку и читает последнюю копию оттуда же; в облако их загружает
клиент. Он должен быть запущен на компьютере с приложением. Путь хранится в `data/folder.json`.

### WebDAV (только через API; у Яндекса — платный тариф)

Бесплатный тариф Яндекса WebDAV не поддерживает («WebDAV is not available for the free tariff»).


1. На id.yandex.ru → «Безопасность» → «Пароли приложений» → «Создать» → тип «Файлы WebDAV».
   Скопируйте пароль (он показывается один раз).
2. На вкладке введите логин Яндекса, этот пароль и название папки, нажмите «Подключить».

Приложение проверит вход, создаст папку и сохранит логин с паролем приложения в `data/webdav.json`
рядом с базой (не в самой базе, чтобы пароль не попадал в копии). «Отключить» удаляет файл.
Тем же способом работают другие WebDAV-облака (Nextcloud и т.п.) через API: `POST /api/backups/webdav`
с полем `url`.

### Google Drive (сложнее)

**Подключение (один раз):**

1. В Google Cloud Console включите Google Drive API и создайте «OAuth client ID» типа
   «Web application». В «Authorized redirect URIs» добавьте адрес, который показывает вкладка
   (например `http://localhost:8000/api/backups/drive/callback`). Открывать приложение нужно по
   тому же адресу, который вы добавили (`localhost` и `127.0.0.1` — разные адреса).
2. Скачайте JSON клиента и положите его в папку приложения (рядом с `app/`, для `Probnik.exe` —
   рядом с exe) под именем `client_secret.json`. Либо задайте `GDRIVE_CLIENT_ID` и
   `GDRIVE_CLIENT_SECRET`.
3. На экране OAuth consent screen добавьте свой gmail в Test users. Пока приложение в режиме
   «Testing», Google отзывает токен через 7 дней — переведите его в «In production» (будет лишь
   предупреждение «приложение не проверено»).
4. На вкладке вставьте ссылку на папку Drive и нажмите «Подключить Google Drive», войдите в
   Google. Токен и папка сохраняются в `data/drive.json` рядом с базой (не в самой базе, чтобы
   токен не попадал в копии). «Отключить» удаляет этот файл.

Доступ запрашивается ко всему Drive (`drive`): приложение должно открыть папку, созданную вами.
Если нужен минимальный доступ, задайте `GDRIVE_REFRESH_TOKEN` через
`uv run python -m app drive-auth <client.json>` — тогда приложение создаст свою папку
(`GDRIVE_FOLDER`, по умолчанию «Probnik backups») и увидит только свои файлы.

Вместо Drive можно использовать Google Cloud Storage: `GCS_BUCKET`, `GCS_CREDENTIALS` (ключ
сервисного аккаунта с ролью «Storage Object Admin») и необязательный `GCS_PREFIX`. Приоритет:
Яндекс Диск (REST), папка с облаком, WebDAV, затем Google Drive из вкладки, затем `GDRIVE_REFRESH_TOKEN`, затем GCS.

**Прошлая версия при импорте.** На шаге «Прошлая версия» мастер импорта CRM показывает прямо на шаге то,
что лежит на подключённом диске: копии приложения (`probnik-….db.gz`) и файлы базы старой программы
(`.db`, `.sqlite`, `.db.gz`). Копию приложения можно «Восстановить»: вся база возвращается из неё (с
подтверждением и страховочной копией), после чего импорт продолжается на шаге «Учителя». Файл старой
программы выбирается кнопкой «Выбрать», и из него переносятся прошлые работы. Если на диске нет ни
того, ни другого или диск не подключён, шаг пропускается сам (его можно вернуть кнопкой «Изменить»).
Загрузки файла с компьютера на этом шаге нет: прошлая версия берётся только из облака.

**Восстановление.** Рядом с каждой копией на вкладке есть кнопка «Восстановить». Она заменяет
рабочую базу данными из копии (ученики, группы, пробники, результаты); перед этим текущая база
сохраняется рядом с ней в `data/before-restore/before-restore-ГГГГММДД-ЧЧММСС.db`, чтобы ошибку можно
было отменить. Копия, сделанная более старой версией приложения, обновляется миграциями. Так же
переносят данные на новый сервер: подключите тот же диск и восстановите последнюю копию. Работает с
SQLite. Вручную: скачайте нужный `.db.gz`, распакуйте и положите вместо рабочей базы при
остановленном приложении. `client_secret.json`, `drive.json`, `webdav.json` и ключи не коммитьте.

## Probnik.exe

Сборка в Windows из корня:

```powershell
./scripts/build-desktop.ps1
```

Готовый файл: `dist/Probnik.exe`. Для его запуска Python и Node.js не нужны.
Exe включает клиент и backend, запускает локальный сервер и открывает системный браузер.
Окно консоли управляет временем работы сервера. База создаётся в `data/probnik.db`
**рядом с exe**; папка должна быть доступна для записи. Через `DATABASE_URL` можно выбрать
существующую базу, в том числе `backend/data/probnik.db`.

Переносимая резервная копия работающей базы создаётся через SQLite Backup API:

```powershell
cd backend
uv run python -m app backup backups/probnik.db
```
